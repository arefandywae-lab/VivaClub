## Main Feature

### 1. Clubhouse (Social Audio / ห้องสนทนาสาธารณะ)

ส่วนนี้คือฟีเจอร์สำหรับสร้างชุมชน (Community) เปรียบเสมือนเวทีเสวนา หรือ Podcast แบบคุยโต้ตอบได้สดๆ

**ทำอะไรได้บ้าง?**

- **Create / Join Room (สร้างและเข้าห้อง):** ใครก็สามารถสร้างห้องสนทนาตามหัวข้อที่สนใจได้ (เช่น "แชร์วิธีแก้เครียดวัยทำงาน") และผู้ใช้คนอื่นสามารถกดเข้าห้องไปนั่งฟังได้ทันที
- **แบ่งโซนชัดเจน (Speaker vs Listener):**
  - Speaker (ผู้พูด): อยู่บนเวที เปิดไมค์คุยได้
  - Listener (ผู้ฟัง): อยู่ด้านล่าง ฟังอย่างเดียว ปิดไมค์อัตโนมัติ
- **Raise Hand (ระบบยกมือขอพูด):** คนฟังที่อยากแชร์ประสบการณ์สามารถกดปุ่ม "ยืนมือ" สัญญาณจะเด้งไปหาคนตั้งห้อง (Host)
- **Moderation (ระบบควบคุมห้องโดยโฮสต์):** โฮสต์มีอำนาจสิทธิ์ขาดในการคุมห้อง:
  - **Invite:** กดดึงคนที่ยกมือขึ้นมาเป็น Speaker
  - **Mute:** สั่งปิดไมค์คนที่พูดแทรก
  - **Kick:** เตะคนปวนออกจากห้องทันที
- **Ghost Identity (ใช้งานแบบไม่ระบุตัวตน):** คนฟังสามารถเข้ามานั่งฟังเงียบๆ โดยใช้ "อวตารและชื่อสุ่ม" (Ghost Profile) เพื่อความสบายใจ

### 2. Telemedicine (ระบบปรึกษาแพทย์ออนไลน์ส่วนตัว)

ส่วนนี้คือระบบสำหรับการรักษาและจิตบำบัดแบบ 1-on-1 (ตัวต่อตัว) ระหว่างคนไข้กับผู้เชี่ยวชาญที่ได้รับการยืนยันใบประกอบวิชาชีพแล้วเท่านั้น

**ทำอะไรได้บ้าง?**

- **Private Consultation (ห้องคุยส่วนตัว):** เป็นห้องปิด (Lock Room) แบบ 1-on-1 ที่คนอื่นกดเข้ามาร่วมฟังไม่ได้ — ปลอดภัยและเป็นความลับ
- **Booking System (ระบบนัดหมาย):** คนไข้สามารถดูตารางเวลาของจิตแพทย์แต่ละท่าน และกดจองคิวล่วงหน้าได้
- **SOS Triage System (ระบบสายด่วนฉุกเฉิน):** หากคนไข้ทำแบบประเมินความเครียดแล้วดิ่งมาก (เสี่ยงสูง) แอปจะปลดล็อกปุ่ม "สายด่วน SOS" ทะลุคิวไปหา "แพทย์เวร (Standby Doctor)" เพื่อคุยฟรี 15 นาทีทันที
- **Monetization / Pay-Per-Minute (ระบบตัดเงินตามนาที):** ในห้องรักษาปกติ ระบบจะจับเวลาตั้งแต่หมอกับคนไข้เชื่อมต่อกัน แล้วจะทำการหักเหรียญสมมติ (Viva Coins) จากกระเป๋าตังค์ (In-App Wallet) อัตโนมัติตามเรทราคาของหมอท่านนั้น
- **No Recording & High Privacy (ห้ามบันทึกเสียง):** กฎเหล็กของห้อง Telemedicine คือจะไม่มีการบันทึกเสียงใดๆ ลงฐานข้อมูล เพื่อเคารพความลับระหว่างแพทย์และคนไข้ (SRTP Encryption)

## ที่มาของปัญหา (Problem Statement)

จากการลองศึกษาแอปพลิเคชันที่มีอยู่ในตลาดด้านสาธารณสุขยอดนิยม (อ้างอิง: Alljit และแพลตฟอร์มอื่นๆ) เราพบ "Pain Point" ทางโครงสร้างที่สำคัญ 4 ประการ ที่เป็นอุปสรรคต่อการช่วยเหลือผู้ที่มีความเครียด

1. **Critical Access (เข้าถึงยากยามวิกฤต):** คิวหาหมอยาวเป็นเดือน เวลาคนไข้อาการกำเริบหนัก (SOS) มักจะต้องรอ หรือได้แค่คุยกับอาสาสมัครที่ไม่ใช่แพทย์
2. **Privacy Concern (กลัวถูกตีตรา):** ผู้ป่วยทางจิตเวชมักไม่อยากให้ใครรู้ว่าตัวเองเข้ามารับการรักษา
3. **Toxic Community (สังคมเป็นพิษ):** มีการเข้ามาปวนด้วยรูปโป๊ หรือการรุมรีพอร์ตกลั่นแกล้งกัน โดยที่แอดมินดูแลไม่ทัน
4. **Passive Help (ได้แค่อ่านเนื้อหา):** ไม่มีการโต้ตอบแบบเรียลไทม์กับผู้เชี่ยวชาญ ทำให้รู้สึกเหมือนคุยกับกำแพง

## การเข้าถึงความช่วยเหลือวิกฤต (SOS Triage System)

**ปัญหา:** ผู้ใช้งานที่มีความเสี่ยงสูง (Severe Critical) ต้องรอคิวนาน

**การทำงาน (Logic):**

- ให้ผู้ใช้ทำแบบประเมิน PHQ-9 (แบบคัดกรองโรคซึมเศร้า 9 คำถาม)
- หาก Algorithm คำนวณแล้วได้คะแนนสูง (> 19 คะแนน) ระบบจะปลดล็อกปุ่มพิเศษ "SOS Call" ในแอปทันที
- คำขอจะวิ่งเข้าช่อง Priority Queue (คิวพิเศษ) ดึงสายให้คุยกับ "แพทย์เวร (Standby Doctor)" 15 นาที เพื่อประเมินอาการเบื้องต้นหรือหาทางออกฉุกเฉิน
- ป้องกันการสแปมปุ่ม: จำกัดสิทธิ์นี้เดือนละ 1 ครั้ง หรือต่อ 1 ผู้ใช้งาน (แต่ในกรณีที่แพทย์ประเมินแล้วมีความเสี่ยงสูง ก็สามารถใช้ SOS Call ได้อีกจนกว่าจะมีสถานะเฝ้าระวัง)

## ความเป็นส่วนตัวในชุมชน (Privacy & Ghost Profile)

**ปัญหา:** ผู้ใช้งานกลัวถูกคนรอบตัว (เจ้านาย/เพื่อน) มาจับได้ว่าเข้าคลินิกจิตเวช

**การทำงาน (Logic):**

- **Preset-Only Policy:** ผู้ใช้งานทั่วไป ไม่สามารถอัพโหลดรูปโปรไฟล์เองได้ เพื่อป้องกันลามกอนาจาร ระบบจะมีคลัง Asset "อวตาร (Ghost)" น่ารักๆ ให้เลือกเท่านั้น และสุ่มชื่อให้ (Random Name)
- **Anonymous Subscription (ตามติดแบบไม่เปิดเผยตัวตน):** กดปุ่ม Follow หมอที่ชอบได้ โดยที่ตัวหมอจะเห็นแค่ตัวเลขยอดผู้ติดตาม (Blind List) รักษาความเป็นส่วนตัว 100% ไม่รู้ว่าใครตามบ้าง
- **แจ้งเตือนเวลาหมอมาเปิดห้องจะเด้งแค่ฝ่ายคนตาม (One-way Notification)**

### อัลกอริทึมการสุ่มชื่อ (Random Name Generator)

แทนที่จะปล่อยให้ผู้ใช้งานพิมพ์ชื่อเองได้อย่างอิสระ ระบบจะทำการดึงข้อมูลจาก "คลังคำศัพท์ที่ปลอดภัย (Safe Word Bank)" มาผสมกัน

**วิธีการทำงาน:** ระบบจะมีลิสต์คำ 2 กลุ่มอยู่ใน Database หรือโค้ดหลังบ้าน:

- **List A (คำคุณศัพท์ - Adjective):** เช่น Happy, Sleepy, Brave, Neon, Cosmic
- **List B (คำนาม/สัตว์/สิ่งของ - Noun):** เช่น Panda, Cloud, Tiger, Moon, Ninja

เมื่อผู้ใช้กดสุ่ม ระบบจะใช้คำสั่ง Random หยิบคำจาก List A และ List B มาต่อกัน พร้อมกับเติมตัวเลขต่อท้าย เพื่อป้องกันการซ้ำ (Unique ID)

**ผลลัพธ์ที่ได้:** ผู้ใช้จะได้ชื่อน่ารักๆ เช่น `Happy_Panda_99` หรือ `Cosmic_Ninja_42`

## ระบบผู้ดูแล และคะแนนความน่าเชื่อถือ (Trust Score & Mod)

**ปัญหา:** คนแกล้งเอาบัญชีผีมาปวนห้องเสียง ปิดไมค์หนี ส่งเสียงดัง

**การทำงาน (Logic):**

- **User Trust Score:** ผู้เล่นมีคะแนนกรรม (Karma) ถ้ารีพอร์ตมั่วๆ จะโดนหักคะแนน แต่ถ้ารีพอร์ตคนทำผิดจริงจะได้บวกคะแนน
- **Auto-Ban Threshold:** ถ้ายอดโหวตเห็นด้วยว่าคนนี้ปวนทะลุเป้า ระบบจะ "เตะ (Kick/Mute)" อัตโนมัติ ไม่ต้องรอ Admin มาอ่านคำร้อง
- **Community Moderator:** เลื่อนขั้นผู้ใช้น้ำดี (คะแนน Trust > 180, ดูทรงใช้งานมานาน 50 ชม.+) ให้กลายเป็น "ผู้คุมกฎอาสาสมัคร" ในชุมชน มีตราอาร์มพิเศษ และมีปุ่มเตะคนออกจากห้องแทนแอดมินกลางได้เลย (มีระบบ Audit หลังบ้านเผื่อ Mod ใช้อำนาจผิด)

### Trust Score Algorithm

ระบบนี้ถูกออกแบบมาเพื่อแก้ปัญหา "การกลั่นแกล้งด้วยการมารุมรีพอร์ต (False Reporting)" โดยใช้หลักการที่เรียกว่า **Weighted Voting (การโหวตแบบให้น้ำหนัก)**

**อัลกอริทึมการคำนวณ (The Calculation Logic):**

1. **คะแนนตั้งต้น (Base Score):** ผู้ใช้งานทุกคนที่สมัครเข้าแอปใหม่จะได้รับคะแนนความน่าเชื่อถือตั้งต้นเท่ากัน (สมมติว่าเริ่มที่ 100 คะแนน)
2. **การได้คะแนนเพิ่ม (Positive Weight):** หากนาย A เห็นคนด่ากันในห้อง แล้วนาย A กด Report ไปที่ระบบ เมื่อ Admin หรือ Moderator ตรวจสอบแล้วพบว่า "ผิดจริง" — นาย A จะได้รับแต้ม Trust Score เพิ่ม (เช่น +10) และเสียงของนาย A ในระบบจะ "ดังขึ้น"
3. **การหักคะแนน (Negative Weight):** หากนาย B เป็นคนหมั่นไส้คนอื่น แล้วไปเกณฑ์เพื่อนมากด Report รัวๆ กลั่นแกล้งคนที่ไม่ผิด เมื่อตรวจสอบ Log แล้วพบว่า "ไม่ได้ทำผิด (False Report)" — นาย B และแก๊งเพื่อนจะโดนหัก Trust Score ทิ้งทันที (เช่น -20)
4. **ระบบจัดการอัตโนมัติ (Auto-Ban Threshold):** ระบบจะทำการ Sum (รวมคะแนน Trust Score) ของผู้ใช้ที่กด Report คนๆ เดียวกันในห้องนั้น หากผลรวมของ Trust Score ทะลุเส้นตาย (Threshold) ที่ตั้งไว้ (เช่น น้ำหนักโหวตทะลุ 500 แต้ม) ระบบจะทำหน้าที่เป็นศาลเตี้ย (Auto-Kick) เตะฝุ่นหรือระงับไมค์ผู้ก่อกวนคนนั้นออกจากห้อง LiveKit แบบเรียลไทม์ทันที โดยไม่ต้องรอแอดมินมนุษย์มาอนุมัติ

## การคุ้มครองข้อมูลส่วนบุคคล (PDPA Compliance)

โครงค้ำจุนที่สำคัญที่สุดสำหรับแอปสายสุขภาพ (Health-Tech):

- **End-to-End Encryption**
- **Data Minimization:** เราเก็บแค่ "Email" ไม่บังคับกรอก "ชื่อ-นามสกุลจริง" ตอนสมัคร คนไข้ข้อมูล Health record ถูกปิดทึบเป็นความลับ
- **Right to Erasure (สิทธิ์ในการถูกลืม):** ผู้ใช้งานมีปุ่ม Deactivate / Delete Account ที่สามารถกวาดลบ Logs ออกจากฐานข้อมูลเราหมดได้
- **No Sound Recording Policy:** ห้องสนทนา Telemedicine ระหว่างหมอกับคนไข้จะไม่มีการบันทึกเสียงลงเซิร์ฟเวอร์เด็ดขาด (No recording in LiveKit Transit) เพื่อเคารพความลับวิชาชีพ
- **Data Consent:** ก่อนเริ่มใช้งาน มีระบบให้กดยินยอม ย้ำชัดเจนว่าเราเก็บ Log การโทรแค่ "เวลาเข้า/ออก" (Duration) เท่านั้น ไม่มีการเก็บเนื้อหาเสียง

## สถาปัตยกรรมระดับซอฟต์แวร์ (Decoupled Architecture) & ความปลอดภัยของระบบ (Security)

### สถาปัตยกรรมระดับซอฟต์แวร์ (Decoupled Architecture)

ทีมใช้วิธีแยกการพัฒนาหน้าบ้าน (Frontend) และหลังบ้าน (Backend) ขาดออกจากกัน (Microservices Concept):

- **Frontend (Mobile):** Flutter (Dart) รันพร้อมกัน 2 แพลตฟอร์ม Android & iOS
- **Backend & API:** Django + Django REST Framework (DRF) เป็นผู้รวบรวม Business Logic และตรรกะทั้งหมด
- **Database:** PostgreSQL วางโครงสร้าง Schema ที่เชื่อมแบบ Relational กัน
- **Audio Signaling Cloud:** LiveKit (WebRTC) หน้าที่ของมันคือการจัดการ "ท่อเสียงสด (Low-Latency Stream)" ซึ่งมือถือจะคุยกับ Server เสียงโดยตรงด้วย Websocket ทำให้แอปเราไม่กินแบนด์วิธของเซิร์ฟเวอร์หลัก (Django)

### ความปลอดภัยของระบบ (Security)

เราดีไซน์ชั้นความปลอดภัย (Security Layers) 4 ระดับ:

1. **At-Rest (หลบอยู่ในฐานข้อมูล):** รหัสผ่าน User ปลอดภัยด้วยการผ่านอัลกอริทึมเข้ารหัสทางเดียว PBKDF2 (HMAC-SHA256)
2. **In-Memory (ตอนยืนยันตัวตน):** แจกแบบ Stateless JWT (JSON Web Token) หากโทรศัพท์หาย Token จะหมดอายุอัตโนมัติ ไม่ต้องกลัวแฮกเกอร์ใช้เซสชันยาว
3. **In-Transit (ตอนส่งผ่านอากาศ):** การเชื่อมต่อ API ถูกห่อด้วย HTTPS (SSL/TLS 1.2+) และเสียงคุยแชทเข้ารหัสด้วยโปรโตคอล SRTP กันใครมาดักฟัง
4. **Hardware Storage:** Token ในเครื่องมือถือ ถูกเซฟตี้ผ่าน Apple Keychain (iOS) และ Android Keystore

## Relational Database (PostgreSQL)

### 1. ตาราง User (บัญชีแม่ข่าย)

ตารางนี้คือ Base User Model ของ Django ใช้สำหรับจัดการเรื่องการล็อกอินและความปลอดภัยขั้นสูงสุด โดยจะเก็บเฉพาะข้อมูลเท่าที่จำเป็น (Data Minimization)

| Type | Field | Constraint | Note |
|------|-------|------------|------|
| uuid | id | PK | Primary Key |
| string | username | | |
| string | email | | Unique constraint |
| string | password | | Hashed string (PBKDF2) |
| boolean | is_active | | |
| boolean | is_staff | | |

**ตัวอย่างข้อมูล (Data Pattern):**
```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "email": "doctor.a@hospital.com",
  "username": "dr_a123",
  "password": "pbkdf2_sha256$600000$Salt$HashedStrig==...",
  "is_active": true
}
```

| int | id | PK | |
| uuid | user_id | FK | 1-to-1 linkage |
| string | display_name | | Randomly generated or chosen |

| string | role | | patient \| doctor \| admin |


### 3. ตาราง Room (ห้องสนทนาเสียง)

ตารางนี้จะถูกสร้างขึ้นชั่วคราว (Lifecycle record) ทุกครั้งที่มีหมอกดปุ่ม "สร้างห้อง" มันเชื่อมชี้กลับไปหาคนสร้าง (GhostProfile) แบบ 1-ต่อ-กลุ่ม (One-to-Many)

| Type | Field | Constraint | Note |
|------|-------|------------|------|
| uuid | id | PK | UUID4 |
| string | title | | |
| string | description | | |
| int | host_id | FK | Link to GhostProfile |
| string | status | | active \| ended |
| datetime | created_at | | |
| datetime | ended_at | | |

