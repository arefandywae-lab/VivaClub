# 4. การทดสอบและ QA (QA & Automated Testing)

ระบบของ VivaClub มีสคริปต์สำหรับยิงและจำลอง (Mocking) สถานการณ์เพื่อทดสอบความยืดหยุ่นและการทำงานแบบอัตโนมัติ สคริปต์ทดสอบทั้งหมดถูกรวมไว้ในโฟลเดอร์ `/scripts/testing/`

## 4.1 ตารางสคริปต์ทดสอบ Backend & API
สคริปต์เหล่านี้เน้นการยิง Request เพื่อสุ่มตรวจพฤติกรรมของ Django

- **`test_api.sh` / `test_api.py`**
  - สเปก: จำลอง Request การสมัครสมาชิกซ้ำๆ สมัครด้วยอีเมลผิดรูปแบบ หรือส่งรหัสผ่านผิด
  - ใช้สำหรับ: เช็กการปัดตก (Reject/Error handling) และความเร็วในการตอบกลับว่าปกติดีหรือไม่
- **`test_clubhouse.py`**
  - สเปก: จำลองการล็อกอินหลายไอดีพร้อมกันเพื่อเรียกเปิดห้อง (Create Room)
  - ใช้สำหรับ: Load test สคีมา Database ว่ารับจังหวะ Query จำนวนมากได้ (ไม่เกิด Deadlock)

## 4.2 ตารางสคริปต์ทดสอบ Real-time Audio Engine (LiveKit)
สคริปต์เหล่านี้เป็นตัวพิสูจน์ระบบเสียง WebRTC โดยจำลอง "บอท (Bots)" ให้ล็อกอินและต่อห้องเสียงเสมือนเป็นมือถือของจริง

- **`test_invite_isolated.py` และ `test_invite_connected.py`**
  - สเปก: เป็นการทดสอบ Handshake โยน WebRTC Token ให้บอทลองเอาไปแตะกับ LiveKit Server ว่าเข้าห้องได้และฟังเสียงได้หรือไม่
- **`test_interactions_connected.py`**
  - ยานแม่แห่งการทำ QA ของระบบห้องเสียง! สคริปต์นี้จะจำลองเอาบอทที่เป็น Host 1 ตัว และบอทที่เป็น Listener 1 ตัว เข้ามาอยู่ในห้องเดียวกัน
  - ตรวจสอบฟีเจอร์ Hand Raise (การยกมือขอพูดผ่าน Metadata)
  - ตรวจสอบฟีเจอร์ Kick หรือ Force Mute ว่า Listener บอทตัวนั้นถูกสับไมค์ลงหลักมิลลิวินาทีจริงหรือไม่ (Test coverage 100% Passed)

## 4.3 การทดสอบฝั่งอุปกรณ์พกพา (iOS/Flutter Integration)
- ปัจจุบันแอปพลิเคชันผ่านการทดสอบเรื่อง **Memory management** (ไม่เด้ง ค้าง เวลาโทรนานๆ) บนอุปกรณ์ **iPhone จริงผ่านสาย Debug (JIT) และ ถอดสาย Release (AOT)** พร้อมสิทธิ์เข้าถึงฮาร์ดแวร์ไมโครโฟนครบถ้วน
